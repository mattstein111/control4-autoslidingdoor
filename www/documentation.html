Auto Sliding Door

Experience-button driver for a motion-sensor-enabled sliding door wired with two contact closures and a position contact sensor.

Hardware model

WireDirectionBehavior
Open Door relayC4 → doorClosed = door slides open; open = closes. Holding closed keeps the door open.
Arm Motion relayC4 → doorClosed = motion sensors armed (they then trigger door open on their own).
Door Contact sensordoor → C4Reports actual door position (open/closed).

Setup

  1. Add this driver to your project (System Design → Search → Auto Sliding Door).
  2. In Connections — Control/AV, bind:
    • Open Door Relay → your physical relay output that controls the door's open trigger.
    • Arm Motion Relay → your physical relay output that arms the door's built-in motion sensors.
    • Door Contact → the contact sensor on the door (recommended; without it the driver cannot report door position).
  3. Set Default Open Duration (s) — how long the door stays open when programming or the Navigator tile calls "Open Door". Default is 5 seconds.
  4. (Optional) Set Hold Duration (s) — a safety auto-release for Hold mode. 0 = unlimited.
  5. (Optional) Bind a keypad button via BUTTON_LINK connections (Open / Off / Hold / Auto) if you want a single-tap mapping. Most users put programming directly on the keypad button and call the driver's Actions, which is more flexible.
  6. To show the experience button in Navigator, enable it in Room Properties → Navigator Tab → Device Visibility for any room and category.

Modes

Actions

ActionDescription
Open DoorCloses the Open Door relay for the configured Default Open Duration, then releases.
Open Door for N SecondsSame, but with an explicit Seconds parameter. Reset semantics if called again while a previous timer is running.
Set Mode to OffBoth relays released. Cancels any pending Open timer.
Set Mode to Hold (Hold Open)Open Door relay held closed. If Hold Duration > 0, auto-releases to Off after that long.
Set Mode to Auto (Motion Sensors)Arm Motion relay held closed. Open Door relay released.
Cancel Pending OpenStops any in-flight "Open Door" timer early. Mode unchanged.
On Button PressedNotify the driver a bound physical button has been pressed. Feeds the built-in gesture decoder (see below). Pair with On Button Released.
On Button ReleasedNotify the driver a bound physical button has been released. Feeds the built-in gesture decoder.

Built-in gesture decoder

The driver includes a state machine that decodes single / double / long-press gestures from a physical button. Wire your keypad/button programming this way:

  • When Button is Pressed → call Auto Sliding Door → On Button Pressed
  • When Button is Released → call Auto Sliding Door → On Button Released

That's it — no custom timers, no helper variables. The driver maps gestures to actions:

GestureResult
Single press (no second press within Double Click Window)If Mode = Off → Open Door. Else → Set Mode to Off (releases Hold or Auto).
Double press (two short presses within Double Click Window)Set Mode to Auto.
Long press (held past Long Press Threshold)Set Mode to Hold. Fires the moment the threshold is crossed, before release.

Timing is tuned via the Long Press Threshold (ms) and Double Click Window (ms) properties.

Events

  • Mode Changed to Off / Hold / Auto — fires when the mode transitions (not on re-set to the same mode).
  • Door Opened / Door Closed — from the contact sensor, post-debounce.
  • Still Open — if Still Open Time > 0, fires when the door has been open continuously that long.

Conditions (for "If..." programming blocks)

  • Mode is Off / Hold / Auto
  • Door State is Open / Closed / Unknown

Variables

  • MODE — string: "Off" / "Hold" / "Auto"
  • DOOR_STATE — string: "Open" / "Closed" / "Unknown"

Navigator tiles

The driver exposes four separate tiles for Navigator. Show or hide each independently per room via Room Properties → Navigator Tab → Device Visibility.

TileTap behaviorIcon
Auto Sliding DoorOpen Door (calls Open Door with default duration)Mode-driven — swaps gray / amber / green to reflect current mode
Sliding Door — OffSet Mode to OffStatic gray (Off icon)
Sliding Door — HoldSet Mode to HoldStatic amber (Hold icon)
Sliding Door — AutoSet Mode to AutoStatic green (Auto icon)

The main door tile never changes mode — it's dedicated to Open Door so casual users (guests, kids) can let themselves out without accidentally locking the door open. Mode selection is on the three dedicated mode tiles.

Typical install: show all four tiles in the kitchen / control room, and only the main door tile in less-central rooms.

Setting a mode you're already in is a no-op — no event re-fires.

Keypad LED feedback

If you bind a Control4 keypad button to one of the BUTTON_LINK connections, its LED color reflects the current mode (configurable via the Off / Hold / Auto LED Color properties).

Behavior notes

  • Setting the same mode that's already active is a no-op — events do not re-fire, LEDs do not re-flash.
  • Any mode change cancels any pending Open-for-N timer.
  • Calling Open Door while in Hold is harmless — the relay is already closed; the timer expires uneventfully.
  • After a Director restart, the driver wakes up in Off with both relays released.

Troubleshooting

Set Debug Mode to On to see verbose Lua output in Composer's Lua Output pane.
